# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # Start Vite dev server (hot reload)
npm run build     # Production build
npm run preview   # Preview production build locally
npm run lint      # ESLint over src/ — must stay at 0 errors (warnings are mostly intentional hook-dependency notes)
```

No test suite is configured. `eslint.config.js` documents every rule override (the React Compiler readiness rules are off on purpose).

## Architecture Overview

Browser-based parametric 3D CAD app, React + Vite. Entry: `src/main.jsx` → `src/AppShell.jsx`, which hosts two apps behind a top-bar tab switch.

### Two apps, both live

- **`src/App3D.jsx`** — the "3D MODEL" tab: Three.js viewport, work planes, feature tree, all solid tools, and the 2D sketch tools used inside a sketch.
- **`src/App.jsx`** — the "DRAWING" tab: a standalone flat 2D drawing app (DXF/PDF output). Not legacy, but it carries its own copy of the 2D sketch engine (`handleMouseMove`, `computeEnd`, `resetDrawState`, … all exist in both). **A fix to a sketch tool usually has to be made in both files.**

### Rendering layers (App3D)

1. **Three.js WebGLRenderer** (`src/Viewport3D.jsx`) — solids, work plane grids, committed sketch geometry.
2. **Transparent overlay `<canvas>`** — tool overlays (snaps, rubber bands, selection boxes, dimension labels, previews), from `viewport3dRef.getOverlayCtx(activePlane)`, redrawn whenever `viewTransform` changes.

### CAD solid modeling

All OpenCascade work runs in a Web Worker:

- **`src/cadEngine.js`** — singleton, promise API over postMessage, lazily starts the worker (`_ensureWorker()`; App3D calls it on mount because OCC takes ~3–5 s to load).
- **`src/cadWorker.js`** — loads OpenCascade.js WASM via replicad; handles every solid operation; keeps built shapes in `shapeStore` (keyed by solidId) and returns mesh buffers. Calls without a `solidId` (live previews) store nothing.
- **`src/cadMesh.js`** — replicad mesh → Three.js `BufferGeometry`.

### Coordinate systems

- **Sketch space (2D)**: pixels, y-down. `SCALE = 2` (1 mm = 2 px); `pxToMm` / `mmToPx` in `src/constants.js`.
- `zoomRef.scale` — mutable camera zoom; snap/select thresholds divide by it to stay constant on screen.
- **Three.js world**: y-up. `w2t(x,y)` sketch → Three.js (y flipped), `t2w(v)` inverse.
- `src/SketchPlane.js` — XY/XZ/YZ mapping (`SKETCH_PLANES`, `sketchToWorld()`); `src/FacePlane.js` — picking and sketching on solid faces. `src/WorkPlanes.js` builds the clickable plane meshes; clicking one sets `activePlane`, tweens the camera and enters sketch mode.

### State patterns

- Sketch state lives in `useState` for rendering, but event handlers read `useRef` mirrors (`linesRef`, `circlesRef`, …, synced by `useEffect`) to avoid stale closures.
- `features` (App3D) is the ordered feature list `{type, id, name, ...}`; sketches store their own geometry; `lines`/`circles`/`arcs`/`splines` are the active sketch buffer. `FeatureTree` is defined inline in `App3D.jsx`.

## Things that aren't obvious

### General

- **Dev gotcha** — editing `cadWorker.js` reloads the whole page (the worker restarts), losing in-memory work.
- **replicad transforms free their input** — `mirror`, `translate`, `rotate` (and `scale`) call `this.delete()` on the shape they are called on. **Never call one on a shape taken from `shapeStore`: `.clone()` it first** (`mirrorShape` and `transformShape`'s Copy branch do). Otherwise the source body's cached shape is freed and every later operation on it fails with "has been deleted" — and a reload replays the same step, so the file looks permanently broken.
- **Keys when focus falls to the page** (both apps) — keys normally reach `handleKeyDown` only via the root div's `onKeyDown` (focus inside the app). Clicking a button that then unmounts (a panel's Apply, Finish Sketch, a popup's Done) drops focus to `document.body`, which used to kill Ctrl+Z / Esc / Enter / every shortcut until the canvas was clicked. A document `keydown` listener hands keys aimed at the bare page (`body`/`documentElement`) to the latest `handleKeyDown` (`handleKeyDownRef`) — only while that app is the visible tab (`rootDivRef.current.offsetParent !== null`; both apps stay mounted, the hidden one `display:none`). Keys typed into inputs never reach it.
- **Errors** — the worker turns raw OpenCascade failures (often a bare number) into plain English in `friendlyCadMessage`; callers prefix them ("Cutout failed: …").
- **Step-bar hints** — each `SmartStepBar` `hint` is a short verb-first sentence; keep that voice.
- **Step ribbon** (`SmartStepBar`, 2026-11-19) — sits across the TOP of the 3D view (it used to be a bar along the bottom). Each step is an arrow: finished steps shrink to a green ✓ (click to go back — `onStepBack`), the current step is filled in the tool colour with its `action` buttons right after it (a label starting with ✓ is filled, `active:true` tinted, others outlined), later steps are grey with no buttons. One hint line underneath; hovering a step shows a longer description from `STEP_TIPS` (keyed by lower-case step label) or the step's own `tip`. Props are unchanged, so no tool needed editing; an action may also be `{node}` (a field, e.g. Extrude's depth box). The step and its options are separate items of one wrapping row, so in a narrow window the options flow onto the next line. **Sketch Cancel / Finish** are in the ribbon too: while a feature tool is sketching (Extrude, Cutout, Revolve, Loft, Sweep, Spring) `sketchFinishActions()` adds ✕ Cancel (`cancelFeature`, `danger` = red) and ✓ Finish sketch (`handleFinishSketch`, `success` = green) through the bar's `extraActions` prop; `cancelFeature` also closes the sketch tool popover (`setFlyoutAnchor(null)`, and the anchor effect cancels its pending frame on cleanup so it can't re-open it), (sketch tools no longer have popovers at all — see Sketch-tool ribbon; the ribbon root still carries `data-step-ribbon` and fires a window `step-ribbon-resize` event from its ResizeObserver); the big CANCEL button left the sketch toolbar, and its FINISH button now shows only for a plain sketch (no feature tool, so no ribbon). The ribbon writes its height to `--ribbon-h` on the viewport container and the ViewCube sits below it; `OffsetDistancePopover` now opens BELOW its button.
- **Sketch-tool ribbon** (2026-11-19; tried on branch `sketch-tool-ribbon`, then merged to main at the user's request) — a SECOND, slimmer ribbon under the main one for EVERY sketch tool in use: `<SmartStepBar compact {...sketchToolRibbon()}/>`. `compact` sits at `top: var(--ribbon-h)`, publishes `--tool-ribbon-h` (the ViewCube clears both) and hides "Esc · cancel". `sketchToolRibbon()` returns {op, color, steps, currentStep, action, hint, onStepBack} or null. All the **Modify** tools are in it (colours from `modifyToolColor`, same as the toolbar): **Move / Copy** (Select → Base point → Place; Move | Copy, COPIES −/+, ✓ Done selecting; then DISTANCE / DIRECTION boxes — Tab hops, Enter locks, the key handler still sees Tab/Esc — + ✓ Lock it in), **Rotate / Copy** (Select → Centre → Angle; Rotate | Copy, COPIES; ANGLE box + ✓ Lock it in), **Scale** (Select → Scale; SCALE × box, ½ / 2×, then click the point that stays still), **Mirror** (Select → Mirror line, two clicks), **Centre** (Select; ✓ Centre on origin). Their pop-ups (CopyModePanel, ResizeScalePanel, MirrorPanel, CenterPanel) are no longer used by App3D — App.jsx (Drawing tab) still has its own. The **Edit** tools too (`editToolColor`): Trim, Delete, Extend get a one-step row whose hint follows the hover (`trimPreview` / `extendPreview`); **Trim Corner** First line → Second line (step from `filletSel.length`; parallel / arc message when `filletPreview` says so; back = `resetFillet`); **Join** Pick an end → Join it (`joinFirstPt`). **Fillet** (Pick two lines (or double-click a shape) → Size; Round | Chamfer, RADIUS / DISTANCE box, ✓ Apply; tooLarge / needLines / corner count in the hint) and **Offset** (Pick → Distance; DISTANCE box shows the live mouse distance as its placeholder, Enter / Tab / ✓ Set distance fixes it, click picks the side) are in it too — their FilletRadiusPanel / OffsetDistPanel flyouts are gone. **Line / Circle** are in it as well (blue): Line = Start → End with Line | Rect | Centre, T / P, and LENGTH / ANGLE boxes + ✓ Lock it in while drawing (`lineLenRef` / `lineAngRef` Tab-hop; Enter locks AND blurs, so the next Enter finishes the chain as before); Rectangle / Centre rectangle = First corner (Centre) → Opposite corner with WIDTH / HEIGHT (`rectW` / `rectH`, one shape); Circle = Centre (Two circles with T) → Size with Circle | 3-pt arc, T, RADIUS (Enter = `applyCircleRadius`); 3-point arc = Start → End → Bend with RADIUS (`arcR`). Simple mode hides `ADVANCED_SOLID_TOOL_IDS`.
- **Shared live preview** — Extrude, Revolve, Loft, Sweep and Spring all show their translucent preview through ONE slot, `Viewport3D.showExtrudeSolidPreview` (kept out of `solidsGroup`, so never picked). An effect may only hide it when it owns the current session, or it wipes another tool's preview. Cut variants are red and glow their targets red (`highlightJoinMembers`, which takes `{solidId, color}`).
- **Cut targets** — Cutout, Revolve/Loft/Sweep/Spring Cut cut every *visible* body the swept box touches (`cutTargetSolids` + `linearCutBoxPx`); hidden bodies are skipped, which is how a user protects one.
- **Move/Copy ribbon** — Move / Copy, Snap Move, World Axes, Set Pivot were already ribbon buttons; once an arrow or ring is armed the DISTANCE (mm) / ANGLE (°) box is now a field IN the ribbon before ✓ Confirm ("✓ Make copy" in Copy mode) — it used to pop out under Confirm via the old `OffsetDistancePopover` (now `OffsetDistanceField`, see Offset planes). The box follows the mouse until you type (`moveCopy3dDistLocked` / `AngleLocked`); Enter still reaches handleKeyDown and confirms.
- **Move gizmo size** — `Viewport3D.showMoveGizmo` builds the arrows/rotate rings once at a FIXED world size (`SHAFT_LEN`/`RING_R` etc., halved 2026-11-10 at the user's request; thickness kept a bit over half so handles stay easy to hit). It doesn't scale with zoom or body size. The handles are picked by click-then-move, not drag.
- **Face vs work plane picking** — `Viewport3D.handleMouseMoveInternal`'s `faceWins`: a body face under the cursor beats a work plane, even when the plane is nearer (the planes stand through the model, so nearest-wins kept opening sketches on the plane). A plane is still pickable where it sticks out past the bodies. **Mirror's Pick Plane keeps nearest-wins** (`mirrorPlanePickArmedRef`) — picking a plane through the body is its point.
- **No clicks while the camera moves** — `Viewport3D.cameraMoving()` (`tween.active`, `TWEEN_MS` = 420 ms) drops click / double-click / right-click / mouse-down during a camera tween (plane/face pick, view cube, Fit); mouse-up still passes so a drag can't stick.
- **Fit** (`Viewport3D.zoomToFit`, key **F**) — measures every visible vertex in CAMERA space (not a world-axis box), skips hidden bodies, resets the scroll zoom (`camera.zoom = 1`) and slides camera + target together so the view angle stays put.
- **Sketch fit** (`fitSketch`, 3D sketch) — `zoomToFit` measures the 3D scene, which doesn't hold the sketch lines (they're on the 2D overlay), so in a sketch F, REFRAME (after turning flat) and DXF import call `fitSketch`: the bounding box of lines/circles/arcs/splines (read through `linesRef`… — it runs from a timer after an import) → `Viewport3D.zoomToWorldPoints(pts, {insetBottomPx:100})`, which fits in camera space and keeps the content above the step bar that covers the bottom of the view. An empty sketch keeps its zoom.
- **Old projects keep the old spline build** (saveLoad `markLegacySplines`, v5) — the single-edge and closed-spline changes below changed the shape of curved bodies made before 2026-11-15, and fillets/cuts made on the old split walls stopped fitting (Zac's 3.6 mm fillet → 1.3 mm max; on the live site his whole body vanished). So `parseProjectData`, for a file saved WITHOUT `splineBuild` (written by `serializeProject` from now on), marks the spline curve segments of every feature created before `SPLINE_CUTOVER_MS` (timestamp in the feature id, else its solidId) `legacy: true`; the worker builds those one Bezier edge per span and never infers them closed (`emitBezierSegs(…, legacy)`, `isClosedSplineSeg`). The mark is saved on the segment, follows mirrors/joins, and disappears when the sketch is re-drawn (fresh segments → new build; anything that then no longer fits shows red). **Never change how a saved recipe builds without a way for old files to keep the old result** — add a replay-set file that exercises it.
- **A spline is ONE edge** (worker `emitBezierChain` → `bezierChainAsBSplineEdge`) — the hand-drawn Catmull-Rom spline's exact Bezier chain is rewritten as a single cubic B-spline (Bezier control points = poles, joins = knots, lowered to multiplicity 2 = C1 via `RemoveKnot`), so an extruded spline wall is one face with no seam lines and its rim is one edge (Fillet picks it whole even with Smooth Chain off). A degenerate span or an OCC refusal falls back to one Bezier edge per span (the old way). Changing it needed `SNAPSHOT_FORMAT_VERSION` 3. **A closed spline** (drawn with C) is built as a CLOSED curve (`catmullRomToBezierSegments(cp, true)`, ending exactly on the wire start): its curve segment carries `closed:true` (detectProfiles), and older saved ones are recognised by `isClosedSplineSeg` (spans the whole profile and its control points do NOT repeat the start — an open spline whose ends were joined does). It used to run open and `close()` added a straight side with two corners (v4). **Polyline splines** (Trim output, DXF import — no Catmull-Rom control points) used to build as their points joined by straight lines (a trimmed half-circle extruded to 67 faces / 195 edges). extrudeMath `polylineCurveRuns` now splits them at sharp corners (> `POLY_CORNER_DEG` 30°) and sends each smooth stretch as an ordinary spline curve segment THROUGH all its points (same shape, one edge: 4 faces / 6 edges); straight stretches stay lines (a DXF rectangle is still 4 lines), a closed one with no corner is one closed curve (`closedPolylineWithCurves`, which restarts the loop at a corner otherwise). Profiles AND sweep paths. **Text letters use their EXACT font curves**: TextPanel stores `glyph: {segs, samples}` on each closed letter contour (one letter per span — L line = 1 point, Q/C curve = `samples` points at t=i/samples); extrudeMath `glyphCurveSegments` solves each curve's control points back from two of its own points (so Move/Rotate/Scale/Mirror, which move the points, keep them exact), groups spans that join smoothly (< 2°) into one `bezchain` curve segment and the worker builds it with `emitBezierSegs` → one B-spline edge (knots spaced by tangent length so G1 joins are C1). Points that no longer fit the structure (a trimmed letter) fall back to polylineCurveRuns. Roboto Bold O: 390 faces / 1164 edges before → 14 / 36. Only newly detected profiles change — saved features keep their stored points, so no snapshot bump.
- **Face DXF** — `projectEdge` (worker) writes lines and view-parallel circles/arcs exactly; any other curve (spline, ellipse, tilted arc) is sampled into ~0.5 mm LINE segments. It used to be ONE start→end chord, which turned spline outlines into a few straight cuts.
- **Sketch tool icons** (`ToolIcons.jsx`, both apps) — vector, in the 3D buttons' glowing-line style, using standard CAD pictures (not game sprites, replaced 2026-11-15) so students recognise them in Fusion / Solid Edge later. One colour per group (`SK`: select green, draw cyan, edit orange, move/rotate/scale/mirror purple, dim yellow). The old Guide button/panel (`GuidePanel.jsx`) was removed 2026-11-15 — the step bar and tool panels replaced it. Each is a `SketchIcon` 48×62 face (same footprint as the old sprites); `c` = main geometry, `g` = faded reference geometry.
- **Top toolbar** (outside a sketch) — FIT, COMPLEX/SIMPLE, MEASURE, FACE DXF, EXPORT STL (moved up from the bottom file bar as the most-used export), X-RAY. STEP export stays in the bottom bar.
- **Broken features** (edit history, `docs/plan-edit-history.md` Session 1) — a cutout / fillet / shell that can't be replayed is SKIPPED and marked broken instead of taking its whole body (and everything built from it) down: `rebuildSolidChain` and the body-edit replay loop in `commitExtrude` wrap each step (a grouped multi-shape cut as one) and call `setBrokenEntry(id, reason)`, with the plain reason from `brokenStepReason`; the step being edited (`overrideId`) still throws as before. A body that can't be built at all on load is listed too, with `Needs X, which couldn't be built` when a feature it needs (`featureNeeds` in `src/tools/featureDeps.js` — base body, mirror source, join members, face-sketch parent; `dependentsOf` gives the downstream set) is broken. `brokenFeatures` (id → reason) is never saved — rebuilt on every replay, reset at project load, entries for deleted features dropped; the Feature Tree shows them red with ⚠ and the reason, a message says how many couldn't update, and the replay harness reports them (`broken`, 'now skipped' vs baseline). `engineBusy` shows 'Updating the model…' when the worker has been busy > 1.5 s. An edit is already one undo step (`feat3d.commit` once before it).
- **Follow the face** (edit history Session 2) — when a body's OWN recipe changes (Extrude gear depth, Extrude re-sketch, Revolve, Loft edit), App3D `followBodyEdit(oldRec, newRec, feats)` asks the worker (`relocatePoints`: builds both BASE shapes, no cuts/fillets) where everything stored on it by position went: each old face a point sits on is matched to the new face facing the same way (planes: same normal, the candidate the point lands on after moving with it; cylinders: parallel axis), the point moves by the least move that satisfies every face it's on, and a fillet point is put on the new edge shared by its two matched faces (kept clear of the ends — a point at a corner would also pick the neighbouring edges). Fillet `edgePoints`, shell `facePoints`, cutouts and sketches drawn on its faces (along the normal only — `shiftFeaturePlanes` also moves each sketch entity's own `facePlane`), and OTHER bodies sketched on its faces (moved whole with their fillets/cuts/face-sketched bodies, rebuilt by `rebuildMovedBodies`) are updated in the saved recipe, then replayed. Points on nothing that moved come back `same` (untouched, so the replay is identical); one that can't be found keeps its place and Session 1's red marking takes over. Face planes now save `solidId`, `point` (click) and `viewCenter`; old files without `solidId` only follow when the plane really lies on that body's face (`strict`). Before this, the Extrude gear depth edit and Revolve/Loft edits rebuilt the bare body and DROPPED its cuts/fillets until reload — they now go through `rebuildSolidChain` (which also keeps a Move). Not followed yet: a body inside a Join (Session 3), a cut sketched on ANOTHER body's face, sketches on cut faces (pocket floors), and edits of a cutout/fillet (only base-recipe edits). Test files: `replay-projects/zz-follow-face*.trc`.
- **Pattern copies follow their original** (edit history Session 3) — a BODY pattern copy (`createTransformedCopy(..., asPattern=true)`) stores `patternOf` (the original feature id) and `patternStep` (list of transformShape params: `{position}` or `{rotation:{angleDeg,axis,pivot}}`). `rebuildSolidChain` builds such a copy with `buildPatternCopyBase`: the original's FINISHED shape from shapeStore (its cuts, fillets and Move included) with the steps applied, then the copy's own ops; its `transform` is not replayed (the steps placed it). `rebuildDependentMirrors` calls `rebuildPatternCopies` first, so every edit of the original updates its copies; Move of the original does too, and Move of a copy appends to its `patternStep`. Old copies (no patternOf) rebuild from their frozen recipe as before (which loses the original's cuts/fillets and puts circular copies round the wrong centre — why this changed). Copies share the original's `groupId` (one tree row), so every "edit this group" lookup in the edit paths excludes `f.patternStep` (else a re-sketch deleted the copies), and copies have no ✎ / gear. If the original is deleted a copy falls back to its frozen recipe. A CUTOUT pattern copy keeps its full recipe + `patternXform` (replays unchanged) and adds `patternOf`/`patternStep`; after the original cutout is edited (gear or re-sketch, which mints new ids) `syncCutPatterns` re-makes each copy from the new original (`remakeCutCopy`) and rebuilds the body; old copies are recognised by `cutPatternCopiesOf` (same body, patterngroup, "<name> Pattern", same profile).
- **Bodies inside a Join / Subtract are editable** (Session 3) — locked member rows of plain extrude/revolve bodies show ✎ and the gear. The normal edit path rebuilds the member (and puts it back in `solids`); at the end commitExtrude sets `joinRebuild`, whose effect (running on the render where the edit is in `features`) removes the members from `solids` again and rebuilds the Join with `rebuildSolidChain` (then any Join that one is in). A member re-sketch must stay ONE shape (refused otherwise). **Moved bodies keep their move through an edit:** a stored Move rotates about the body's own bbox centre, so `keepMoveAfterEdit` (worker `baseCenters`) adjusts `transform.position` by (R − I)(c_new − c_old) — the same rigid move, the body grows/shrinks from its sketch (mouse2: shortening the Subtract's hole bodies used to slide the scoops along). Re-sketch used to DROP a body's Move and its colour; both are kept now.
- **Model health readout** (Ctrl+Shift+H, hidden developer view, never saved) — `ModelHealthPanel` (App3D, bottom-left of the viewport) lists every visible body: faces / edges by kind, volume, and flags — red: OCC says INVALID (`shapeIsValid`), more than one solid in a body, no solid; amber: tiny edges (< 0.05 mm) / faces (< 0.05 mm²), or > 60 flat faces making up most of the body (a curve probably built from facets). Re-measured 300 ms after `solids` changes while open. Worker `shapeHealth` → `shapeHealthOf` (replicad `faces`/`edges` + `geomType`, BRepGProp lengths/areas, a TopExp_Explorer over SOLIDs); cadEngine passes `health` through. Use it to find the next 'why is this split into pieces?' problem: a simple part should have few faces.
- **Replay harness** (open the 3D tab with `?replay`; `src/tools/ReplayPanel.jsx`) — rebuilds a batch of .trc projects from their RECIPES (snapshots ignored, worker `clearShapes` first) via App3D `replayForTest` → `rebuildProjectFromFeatures(features, null, report)` and reports per project: bodies that failed, time per body, the worker's fallback log (`diag()` → `takeDiagnostics`: cut one shape at a time, cut tolerance retry, looser fillet setting, partial fillet, circle cut re-cut, spline built in pieces, sweep path re-fitted, cache-miss rebuild) and every body's health. Projects come from `replay-projects/` (git-ignored — student work is never committed; dev server only, via import.meta.glob) or Add files… (read locally). `replay-projects/baseline.json` (from Save as baseline) makes it a regression test: red when a body now fails, a volume changes > 0.5 %, solids change or a shape turns invalid. **Add a `diag()` call to any new fallback path.** Heavy worker steps are wrapped by `timed()` (cut, fillet/chamfer, overlap check, join fuse — the `…Untimed` functions) and log `slow step` when over 1 s; those show only in a row's detail, not as problems or baseline changes. Dev builds expose `window.__cadEngine`, `window.__replayResults` and `window.__setReplayBaseline` for console work. First run (2026-11-15, 14 files): Mirror rebuilds its loft source from scratch (loft.trc: loft 8.1 s + mirror 7.7 s); Subtract with softened members is slow (mouse2 26.5 s, mouse3 10.3 s).
- **X-ray** — `xray` state (key **X**) fades solid faces and drops edge depth testing in `Viewport3D`. View-only, never saved.

### Saving

- **Autosave** — re-writes ~3 s (file) / ~10 s (cloud) after `features`/`solids` settle, ONLY once `projectFileHandleRef` or `cloudProjectIdRef` exists (never opens a picker). `autosaveBaseRef` holds the last text written; manual saves must call `markSaved(kind)`. - **Project snapshots (fast open)** — a save is the feature recipe PLUS each body's B-rep (`shape.serialize()`, gzip + base64) in `snapshots:{version, fingerprint, shapes}` (worker `snapshotShapes` / `restoreShapes`). **The recipe is the source of truth; a snapshot is a throwaway cache — any mismatch or failure falls back to full replay, never an error.** Rules: `collectShapeSnapshots` caches per `solid.group` and returns `null` while `cadEngine.pendingCount > 0`; `parseProjectData` accepts snapshots only if `featuresFingerprint` (features minus name/colour/hidden) matches; `saveProjectFileAs` awaits snapshots AFTER the file picker (it needs the click's activation); autosave compares recipe-only text; cloud caps at `CLOUD_SNAPSHOT_BUDGET` (1.5 MB, a guess). **Any new way to change a body must produce a new `solid.group` (go through `replicadMeshToThree`) or the cache goes stale.**

- **Fillet** — no Lock step (`fillet3dAccepted` = `fillet3dSel.length>0`). Once an edge is picked the size is in the step ribbon (2026-11-19; the radius pop-up is gone): RADIUS / DISTANCE box (autofocus, Enter = `commitFillet3D`), Fillet / Chamfer, Smooth Chain, ✓ Apply; `fillet3dNote` (e.g. the largest radius that fits) shows in the hint line. `fillet3dHandlePos` is still set but no longer drawn. On failure `cadEngine.filletMaxRadius` (bisection) pre-fills the largest working radius. Picked = yellow, hover = orange (shared with Soften). - **Smooth** (2026-11-18, replaces Soften in the sidebar) — rounds EVERY outside edge and corner of a body by one radius (inside corners stay sharp), optionally keeping picked flat faces flat with a crisp edge. It never asks OpenCascade to fillet: `tools/smoothMesh.js` `smoothSolidMesh(mesh, {radius, keepFlat})` does a morphological OPENING of the body's display mesh on a grid (cell = r/3.5 within 12 M cells): voxelise → "core" = points ≥ r deep (rough grid EDT, then exact BVH depth in the band near r; each core cell at the edge stores exact core-surface points: nearest-point sample + regula-falsi crossings toward non-core neighbours) → f = distance to the core − r (feature transform to the nearest core cell + its neighbours' samples; in the band |f| < 1.2 cells an **inward walk** — step away from the nearest point of the part until r deep, repeat — lands exactly on the core's edges/corners, which samples miss by up to a cell) → clip at keep planes → surface nets + Taubin. Keep-flat: past a keep plane the part is treated as carrying straight on (points PROJECT onto the plane for inside-ness and depth, like extruding the face's outline), its triangles are left out of the depth measure, and the result is cut at the plane; a keep plane that no longer touches any triangle (body moved/re-shaped) is dropped and that face just rounds (`keptFlat` reports how many held). Accuracy on test boxes: within 0.25 mm of a true round, volume within 0.6 %. ~1–7 s (arch shape r = 2: ~4–6 s in the worker); runs in `smoothWorker.js` via `smoothClient.smoothMeshAsync`. Thin parts (< 2r) are worn away and sharp points pull back (a 38° tip at r = 2 retreats ~4 mm) — the panel says so; a bbox-shrink warning was tried and dropped (it can't tell a pointed corner from a thin fin). **Smooth is always the body's LAST step** (user decision): the feature `{type:'smooth', solidId, radius, keepFlat:[{n, d, p(mm)}]}` only changes what is SHOWN — the App3D effect after the Smooth section swaps the face mesh's geometry inside the body's own group (raw kept in `group.userData.rawFaceGeo`, `userData.smoothed`/`smoothKey`), takes the edge lines off every layer (not drawn, not raycast), and puts the raw mesh back when the feature goes or while the Smooth tool edits that body. B-rep, rebuilds, replays and snapshots never see it (`rebuildProjectFromFeatures` and `collectShapeSnapshots` skip `type:'smooth'`). Results are cached (`smoothCacheRef`, last 4) by settings + a checksum of the raw mesh, so delete → undo (which rebuilds bodies) is instant. Faces of a smoothed body can't be picked: Viewport3D gives no face hover on a group with `userData.smoothed` and a face-pick click there calls `onSmoothedFaceClick` → `refuseSmoothedPick` ("Delete Smooth to keep modelling it"); `handleFaceClick` checks `isSmoothedSolid` too. Export STL writes smoothed bodies from the on-screen mesh (`mergeSmoothedIntoStl` appends them to the worker's fused binary STL of the rest); STEP export has the sharp body. Tool: body (lone body auto-picked) → click faces to keep flat (yellow outline via `dxfSelectedFaces`, click again to drop) → RADIUS box in the step ribbon (2026-11-19; the floating radius panel and `smooth3dHandlePos` are gone — the thin-parts warning is in the hint line and the box tooltip), Clear flat faces, ✓ Smooth → Enter. Picking a smoothed body (or its row's ruler, `handleEditSmooth`) edits its Smooth. Deleting a body owner also drops its Smooth; a Join consumes it (un-join restores). A failure marks the row broken (`setBrokenEntry`).

### Drawing tab — orthographic views

- `computeOrthoViews` (worker) uses OpenCascade hidden-line removal (`hlrViewEdges`, all bodies in ONE run). **Never put shapeStore shapes in a compound — that deletes them.** Hidden edges come back `style:'dashed'`; flat runs (circles seen edge-on) become lines (`straightRun`). Centre-line axes come from `roundAxes` (cylindrical faces grouped by axis + radius, kept if they wrap ≥180°, so fillets are excluded).
- `OrthoViewsPanel` → `tidyView` (visible beats hidden in the same place, no duplicates) → `layoutOnSheet` at a standard scale (`autoScale` picks the biggest `DRAWING_SCALES` entry fitting the page; 20 mm paper gap), centred on the origin where the page sits. Centre lines are `style:'center'` (a full style alongside `'dashed'`: canvas `applyEntityStyle`, PDF `applyStyle`, DXF CENTER). Labels and the scale note are line entities from `strokeFont.js` with `text:true` (no end dots).
- **Drawing-tab dimensions** — the DIM button's flyout (`DimPanel.jsx`, state `dimMode`: `hv` | `aligned` | `circle` | `angle` | `chain` | `baseline` | `hole` | `note`) makes kinds `ortho` {x1,y1,x2,y2,orient,pos}, `linear` (aligned), `diameter`/`radius`, `angle` {cx,cy,start,sweep,r,reach}, `hole` {cx,cy,r,angle,count} (`holeCount`: same-radius circles in the same `view`), `leader` {x1,y1,x2,y2,text}. - **Dimensions read real size** — view entities carry `viewScale`; the DIM tool copies it to `dim.scale` (from the picked circle/arc, or via `viewScaleNear` for linear dims) and every dim text (canvas, preview, PDF) is `pxToMm(len) / (dim.scale || 1)`, independent of the PDF print scale.
